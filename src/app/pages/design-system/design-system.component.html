Design System — O Campista

Referência viva dos tokens e padrões visuais do app. Tudo nesta página é renderizado com os mesmos var(--token) e classes globais de src/styles.scss — se algo mudar lá, muda aqui. Todo elemento visual novo do projeto deve sair daqui antes de ser inventado do zero.

@for (secao of secoes; track secao.id) { {{ secao.label }} }

Princípios

  1. Sem framework de UI. Nenhum Material, Bootstrap ou Tailwind. Todo componente é SCSS puro sobre os design tokens.
  2. Token antes de valor literal. Nunca hardcode hex, px de espaçamento, raio, sombra ou font-size quando existe um token equivalente.
  3. Reaproveite o padrão existente. Antes de criar uma classe nova, procure o card/badge/modal/formulário mais parecido no app e copie a estrutura de classes dele.
  4. Global só com 3+ usos. Uma classe só sobe para styles.scss quando o padrão se repete em três ou mais componentes. Caso contrário, fica no .component.scss.
  5. Dark mode é automático. Se o componente usa apenas var(--token), o tema escuro já funciona. Nunca escreva [data-theme='dark'] .minha-classe dentro de um componente — a única exceção são cores que não vêm de token (gradientes e rgba customizados).
  6. Acessibilidade e i18n não são opcionais. WCAG AA, checks AXE limpos, TranslatePipe em todo texto visível e chaves em pt-BR.json e en-US.json.

Esta página é documentação interna de desenvolvimento e, como as páginas de Termos e Privacidade, é a única exceção à regra de i18n: seu conteúdo é fixo em pt-BR.

Botões

Altura fixa de 40–48px, --radius-md, font-weight: 700 e --transition-base. Hover do primário escurece, sobe 1px e ganha sombra colorida; :active remove o deslocamento; :disabled vai para opacity: 0.6 e cursor: not-allowed.

Ação destrutiva sempre passa por ConfirmDialogService — nunca window.confirm() ou alert().

Cards

background: var(--color-surface), --radius-xl (ou --radius-lg em cards menores), --shadow-sm em repouso, border: 1px solid var(--color-border-light) quando não é flutuante, padding interno --space-4/--space-5 e entrada com cardAppear.

Card padrão

Use a classe global .card-elevated — não recrie superfície + sombra.

Card flutuante

Painel sobreposto ao mapa: --shadow-lg e sem borda.

Badges e pills

--radius-full, padding curto, font-weight: 700 e --text-xs. Estado semântico sempre em par background: var(--color-X-bg); color: var(--color-X).

Sucesso Erro Atenção Neutro

Indicador de status

O padrão canônico de status é o .badge-ocupacao de card-camping.component.scss: fundo rgba(cor, 0.12) com borda rgba(cor, 0.3). Reutilize esse padrão para qualquer novo indicador.

🟢 Tranquilo 🟠 Movimentado 🔴 Lotado
Ícones são emoji. O app não usa icon set. Um emoji com significado precisa de aria-label no elemento pai — leitores de tela não o anunciam de forma confiável sozinho.

Formulários

Inputs de 44–48px de altura, --radius-md; no :focus a borda vai para --color-accent com anel 0 0 0 3px rgba(249, 153, 32, 0.25). Sempre Reactive Forms (FormBuilder/FormGroup tipado) — nunca ngModel.

Campo obrigatório — bloco com fundo e cor semânticos de erro.

Feedback

Transiente é ToastService (success/error/warning/info); confirmação é ConfirmDialogService. Nada de alert() ou confirm() nativos.

Responsivo

Dois breakpoints em todo o app — não invente um terceiro sem necessidade real. O layout é escrito primeiro para desktop e sobrescrito com max-width depois (o app não é mobile-first; siga o mesmo padrão por consistência).

max-width: 768px Tablet/mobile: layout empilhado, painel lateral escondido, painel flutuante vira bottom sheet.
max-width: 480px Celular pequeno: menos padding, logo menor, larguras fixas viram 100%/90vw.
Bottom sheet. Abaixo de 768px, painéis flutuantes trocam position: absolute por fixed; bottom: 0; left: 0; right: 0, mantêm border-radius só no topo, entram com slideUp e podem ter um drag handle (::before de 40×4px centralizado). Referência: .camping-info em card-camping.component.scss.

Checklist antes de abrir o PR

  1. Existe componente parecido? Copiei a estrutura de classes dele antes de criar do zero.
  2. Toda cor, espaçamento, raio, sombra e fonte vem de var(--token).
  3. Testado em 768px e 480px.
  4. Testado com o tema escuro ativo.
  5. Chaves i18n adicionadas em pt-BR.json e en-US.json.
  6. aria-label, ordem de foco e contraste revisados (AXE limpo).
  7. Loading, vazio e erro tratados — não só a UI feliz.
  8. npx prettier --check ., npm test e teste manual no navegador.
